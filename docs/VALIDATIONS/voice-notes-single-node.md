# VALIDATIONS — voice-notes patterns on a single node

Validation of the single-node model (docs/ARCHITECTURE.md) against the real
`voice-notes` pattern set (patterns/*.yaml), 2026-08-27. Input: the four YAML
files described in LEG-010 terms: `main`, `atomic` (tool/linguistic), and
`composite` (sequence/parallel).

## Setup

One node serving its full roster locally: 9 mains (starting agents) + the
`simple_transcription` tool + 16 linguistic atomics + composites
`draft_writing`, `executive_summary_flow` + the 9 inline parallels generated by
the mains. Each agent = one queue + one pool; one beaver; API + mini-manager.

## Traces

### `idea` (smallest main)

`[simple_transcription → parallel [simple_summary, categories, key_ideas]]`

1. **API** `submit(idea, {audio})` → `task_id T`, inputs staged, root token
   `[idea]`, `root=True`, `ultimate_return=client:T` → queue `idea`.
2. **idea** (sequence, index 0) deposits to `simple_transcription` (tool). Result
   `{transcription, language}` returns to idea's dual queue.
3. index 1 → parallel inline → deposit to `idea_text_processors` (its own dual
   queue + call-frame) with the DAG `[simple_summary, categories, key_ideas]`.
4. Fan-out to the 3 queues; each child returns to `idea_text_processors`;
   **fan-in dedupe by DAG path, scoped per (parallel agent, task_id)**.
5. **Merge = flat union** `{summary, categories, key_ideas}` → idea accumulates
   flat `{transcription, language, summary, categories, key_ideas}` → final
   index → delivery to `client:T` (results board).

### `blog_post_draft` (heavier main, nested composite)

`[simple_transcription → parallel [simple_summary, categories, key_ideas,
main_goal, draft_writing]]`

1. Same until the parallel fan-out, which includes `draft_writing`
   (sequence `[article_outline → inline-linguistic draft]`).
2. `draft_writing`: step 0 `article_outline` with `output_as: outline_data`;
   step 1 is an **inline linguistic stage** (prompt embedded, unnamed) that
   reads `input.transcription` and `outline_data.outline`.
3. Everything converges: parallel merges `{draft}` with the rest → sequence
   joins it with `{transcription, language}` → client.

### Result without structural changes, but with four concrete refinements

The model (dual queues, root token, per-task boards, pools over shared
atomics, delegation) validates the whole set on one node. The real patterns,
however, force four contract-level refinements — H1–H4.

## Refinements surfaced (H1–H4)

- **H1. Inline stages.** YAML uses unnamed stages with embedded prompts
  (linguistic) and named inline parallels (`idea_text_processors`). Contract:
  *inline parallel → auto-named agent* (own queue + join); *inline linguistic →
  self-executed by the owning composite* (no intermediate queue). Moved into
  LEG-010.
- **H2. Dotted template paths + system vars.** Prompts use `{input.transcription}`,
  `{outline_data.outline}`, `{input.language}`, `{current_date}`. Contract: the
  blackboard is **composite-scoped** (nested `input`, `outline_data`, …) and the
  templating engine resolves dotted paths plus system variables (e.g.
  `current_date`). Without this the real prompts cannot be filled. Moved into
  LEG-010.
- **H3. Merge semantics.** `executive_summary_flow` merges children without
  collisions; `names_and_entities` emits *two* keys (`persons`, `companies`);
  sequences accumulate flat. Contract: merge = **flat union of child outputs**,
  rename via `output_as` when keys collide; sequences accumulate flat. Moved
  into LEG-010.
- **H4. Schema compilation.** `output_schema` needs unions (`["string","null"]`),
  arrays, nested objects and recursion (`outline`). Compiled to pydantic with
  deferred refs; validated at the queue boundary. Moved into LEG-010.

## What the traces confirm

- **Two `B`s = two tasks**: every occurrence of a shared pattern is a distinct
  `task_id` + DAG path; per-task boards (`blackboard:{node}:{task_id}`) prevent
  cross-talk (e.g. concurrent `simple_summary` across different mains).
- **Dual-queue fan-in works** for both sequence and parallel when the DAG path
  (not the agent name) is the dedupe key.
- **Pools over shared queues**: `simple_transcription` and the shared atomics
  are natural pool points on a single node.
- **Root token semantics** (final derived from position, delivery to
  `client:{task_id}`) hold for all nine mains.

## Status

Model validated on a single node against the real voice-notes set. H1–H4 are
acceptance criteria for LEG-010 (patterns v1). A follow-up may translate two of
these patterns into YAML legio v1 as a conformance fixture.
