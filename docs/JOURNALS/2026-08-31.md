## Work done (per issue)
- **S1 design thread closed (addenda O+).** The one-agent-spec proposal was
  confirmed by the maintainer ("si escribe esto"). Key rulings absorbed:
  - **`input_as` is mandatory** for every agent. Without it, "input" is a
    convention a loader cannot check; the anti-convention rule makes it an
    explicit, checkable alias (no reserved words as read roots).
  - **Entry + output contracts mandatory for ALL agents** (atomic and
    composite), not only `main`. Text/json/binary decide where a value lives.
  - **Reuse belongs to every definition** (atomic and composite, tool and
    linguistic use the same spec): definitions are source-agnostic; wiring
    (`bind:`) lives at the usage site; the same agent can bind the same
    variables to different producers in different composites.
  - **Chain-wide composability verification:** `{from: P.path}` resolves
    against the whole chain preceding the node in scope (the encapsulating
    composite's `input_as` or ANY earlier child's `output_as`), built up from
    anything in the chain — not only the immediate predecessor.
  - **Gaps 1–5 closed into the spec:** composite output composition (`emit:`);
    parallel children bind only from the composite's `input_as` (serial deps
    nest as a sequence in a branch); interior↔contract coherence (tool
    `input_schema` ⊆ registered signature at load; linguistic prompt `{var}`s ↔
    `input_schema`); encapsulation (`output_as` unique per scope, cycles
    rejected at catalog load); strict `bind` (extra keys error, required
    covered, omitted = default) + static type compatibility on the edge.
  - **Deposit semantics:** deposits never merge flat into the top level (top
    level reserved for the entry); each deposit nests under its `output_as` (or
    its `name`) — read semantics inherited from the reference (flat merge +
    `output_as` namespacing).
