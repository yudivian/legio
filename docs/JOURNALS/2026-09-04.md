# 2026-09-04 — Session 31 — Fase 3: unified CompositeAgent runner + schema/loader at `type: composite` + `branches`

## Scope

Implement the unified composite engine end-to-end after the Session 30 contract
rewrite: Schema 1 discard of `AgentKind.SEQUENCE|PARALLEL` (`branches` field),
the loader resolving branches to `(class, input_as)` routes, the single
`CompositeAgent` runner (ramify → gather → build `output_as`), and rewrite of
every test that booted the old `SequenceAgent`/`ParallelAgent`.

## Work done (per issue)

- **LEG-044 / LEG-040-composite / LEG-043 (code)**: created
  `src/legio/agents/composite_agent.py` — the one runner. `_fan_out` deposits
  each branch as its own loader-resolved `level_route`, `current_index=0`,
  `level+1`, `end_of_level_queue` = this composite's gathering queue (collapsed
  onto its own queue by message-type dispatch), a **fresh `branch_id`
  (uuid4)** per branch, same `task_id`, and the shared input re-keyed under the
  first step's `input_as`. `_fan_in` fetches state by `task_id` (O(1), no
  scan), accounts one result per `branch_id`, joins on all-complete, builds
  `output_as` and decrements `level` to resume (`_resume_level` via the uniform
  `_route_outcome`). Handles single-branch (sequence) and multi-branch
  (parallel) uniformly; a `type: composite` step stays in a branch's route and
  is invoked recursively through its inbox.
- **LEG-044 (loader)**: `loader.py` — `resolve_branch`/`resolve_composite_branches`
  expand bare branch names to `(class, input_as)` routes; `load_patterns` now
  uses `yaml.safe_load_all` so a single YAML stream with `---` multi-docs loads
  every spec; composite branch validation checks unknown references, and tool
  step parameters are validated against the union of the enclosing composite's
  input scope and the sibling output under the step's `input_as` (resolves both
  `{text}`-style and `{title}`-under-`input_as`-style, matching the runtime
  re-keying).
- **LEG-044 (schema)**: `schema1.py` — `AgentKind` reduced to `tool|linguistic`,
  `AgentSpec.kind` now `None` for composites, `branches: list[list[str]] | None`
  replaces `sequence`/`parallel` (from previous in-flight session state).
- **LEG-044 (routing)**: `sequences.py` — `starting_route` uniform: atomic and
  composite roots both yield `((spec.name, input_as),)`; the composite
  concretizes its fan-out (no old `_collect_sequence_route`).
- **Tests**: rewrote `test_leg040_sequence_agent.py` (composite single-branch /
  sequence contract), `test_leg041_parallel_agent.py` (fan-out/fan-in, 7
  cases, now on `CompositeAgent`), `test_leg043_examples_composites.py`
  (REST sequence + parallel-root examples on the unified runner),
  `test_leg032_example_summarize.py` (REST ling→tool via CompositeAgent).
  `test_leg010_patterns_schema.py` multi-doc fixtures now load.
- Deleted `src/legio/agents/sequence_agent.py` and `parallel_agent.py`;
  `agents/__init__.py` and `patterns/__init__.py` re-export only the unified
  surface (`CompositeAgent`, `resolve_branch`, `resolve_composite_branches`).

## Logging added

  pending), INFO `composite joined` (all branches present), plus the inherited

- `loader.py`: INFO `patterns loaded` (count) already present; branch

- `uv run python -m pytest tests -q` → **131 passed**.
- `uv run ruff check src tests` → All checks passed.

- Validation cases: LEG-043 (sequence + parallel-root REST examples) and

## Decisions taken

- A composite's branches close to the composite's **own gathering queue**
  (collapsed onto its inbox, dispatched by `message_type`): the branch result
  returns to the parent composite for fan-in, then the composite resumes its own
  level carrying the outer-assigned `end_of_level_queue`/`level` (covered by
  `test_parallel_resume_preserves_its_own_branch_id` and the rewritten
  `test_sequence_preserves_level_and_end_queue_for_branch`).
- `CompositeAgent.branches` is a list of **routes** (each branch = a sequence of
  `(class, input_as)` steps). Single-step test branches are wrapped accordingly.
- `composite_agent.py` uses `db.dict` for the in-flight join continuation keyed
  by `task_id` — no scan, no lock, nothing sleeps (rule 8).
- No new dependencies: `uuid` is stdlib; `yaml.safe_load_all` uses the existing
  PyYAML.
- Composite payload: each branch produces `{output_as: <value>}`; the composite
  gathers and wraps them under its own `output_as` (construction, not
  accumulation, matching LEG-043 assertion shapes).

# 2026-09-04 — Session 32 — Re-audit (rule 12) of the CompositeAgent against ARCHITECTURE/LEG-040

## Scope

Rule-12 re-audit of the shipped unified composite implementation (Session 31)
against `docs/ARCHITECTURE.md` §3/§7 and `docs/CONTRACTS/LEG-040-composite-agent.md`,
fixing any deviation found rather than deferring it.

## Work done

- Audited `CompositeAgent` against ARCHITECTURE §3 (fan-out / fan-in / branch_id /
  re-keying), §7 (lifecycle, tolerant fan-in), §8 (failure), and the LEG-040
  contract. Confirmed the implementation matches every design point: each branch
  gets its loader-resolved route at `current_index 0` / `level+1` / autogenerated
  uuid4 `branch_id` / gathering-queue closer / re-keyed input; fan-in keyed
  `(task_id, branch_id)`, idempotent join exactly once; build `output_as`; resume
  with the creator's closer; nested and composite-as-root covered by tests.
- **Deviation found and fixed**: ARCHITECTURE §3 requires the **submit** to assign
  the **root `branch_id`** — "every message of the flow carries one (never
  empty)". `manager.submit` deposited the root `ExecutionRequestMessage` without a
  `branch_id` (defaulted to `""`). Fixed: `submit` now autogenerates a
  `root_branch_id` (uuid4) carried on both the stored `FlowToken` and the
  deposited root request.
- **Deviation checked and cleared**: ARCHITECTURE §7.5 "under lock —
  `state:<composite>`" maps to the repo-wide `db.dict` bookkeeping (as in
  base.py, manager) where the poller owns its queue/state — not an async mutex;
  consistent with polling-only (rule 8). No change.
- Added a contract test in `tests/test_leg014_manager.py`: the root token and the
  deposited root request both carry a non-empty `branch_id`.

## Logging added

- None. `manager.submit` already logs the submit; no new event required.

## Decisions taken

- No async-lock abstraction is introduced; `db.dict` is the repo-wide bookkeeping
  mechanism and satisfies the §7.5 "lock" intent under polling-only (rule 8).
